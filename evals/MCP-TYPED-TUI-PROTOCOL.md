Preregistered on 2026-09-13 after the two preserved failures described in
`MCP-TUI-RESULTS-20260913.md`. Prime explicitly confirmed READY for the object
`foundry_run.input` contract, required input argument, separately named
`foundry_run_json.inputJson` contract and native skill explanation. This is a new
diagnostic interface condition, not a replacement for either earlier result.

The original NumericRollup natural-language task is unchanged for the first
session. No workflow template, nodes, output solution or manual candidate edit is
supplied. The only product intervention is the advertised transport contract and
its native skill explanation. The object route is preferred; use of the explicit
JSON-text route is recorded separately. No implicit input coercion is permitted.

At most THREE actual TUI sessions may start across this campaign, each with a
240-second wall ceiling. Only one owned TUI is active at a time. Main and small
models must be observed in the actual isolated OpenCode catalog with every price
explicitly zero. Actual exported session and assistant model IDs and costs must
match. No paid fallback, headless generation, manual candidate repair or model
call outside these sessions is allowed. An unavailable provider is reported
separately from construction and execution failures. A new session after a failure
may receive only recorded diagnostic feedback concerning one causal interface
issue, with that assistance preserved. Do not spend further sessions without a
specific recorded reason.

Freeze complete Foundry src/bin/schemas, the four selected native skills, all
installed Node dependency bytes (including their licenses and internal symlinks),
the evaluator and its helper sources, package manifests, protocol and original
task before a TUI starts. Freeze the installed Node and OpenCode executable bytes
as well. Record before/after source inventories and reject a changing acquisition.
Read-only mounts use these copies, never the live repository's node_modules.
System libraries and OS files remain the observed host platform; record binary
identity, OS metadata and shared-library identities without claiming an OS image
freeze. Later attempts reuse the same frozen program unless prime explicitly
authorizes a separately recorded causal product revision.

Use fresh synthetic projects and isolated XDG state. Host home and credentials
are absent. Run the actual project installer with `--client opencode --no-hooks`;
preserve its generated MCP command and journal. Allow only selected native skills,
read access to task inputs/installed skills, the model's output.json locator, and
the local Foundry MCP tools. No model shell, web, plugin, subagent, global settings,
arbitrary file access or approval/answer tools are exposed. Capture an actual
PTY/tmux transcript, screens, process outcome and raw exported tool arguments.

Required whole-path evidence: native workflow-foundry skill load; a model-owned
request-bound design-context call; validation of the exact submitted candidate;
proposal and apply responses for that request; a successful actual run bound to
that candidate with the sample input; real inspect/event evidence; and a final
assistant response plus exact model-write provenance for the four-field locator
requestId/proposalId/workflowId/runId. Preserve the candidate and the entire task
workspace before independent replay. Successful partial tool calls are reported
even when the whole-path gate fails.

Independent replay uses the real MCP SDK Client/StdioClientTransport against the
frozen MCP server in a network-disabled namespace. Save the exact model candidate
without edits in a separate control workspace. Test sample [3,7,11], changed [2,5],
empty [], nonnumeric [1,"2"], missing values and non-array values. Also reject
serialized object arguments on the object route, missing transport input and
malformed/double-encoded JSON on the explicit text route. JSON-text sample execution
is a separate transport control. Check exact artifact JSON, workflow hash, full
event chain, persisted event head, actual artifact completion, bytes and SHA-256.
Invalid cases must reject or fail without new artifact bytes or false success.
No arbitrary shell/approval/answer capabilities may appear in the MCP catalog.

When the first whole path and independent cases pass and a session remains,
exercise a second natural-language request: add output field `values` containing
the unchanged numeric input array, leaving total and count behavior intact. Use
a fresh TUI state with the preserved original Foundry workspace, bind the request
to its prior workflow hash and require a new immutable version. Re-run the old
hash and inspect its old run to prove version/run preservation. The old task and
all old outputs stay intact. This is an exposed diagnostic editing task, not an
unseen evaluation.

Raw provider-facing schema/argument evidence or pinned OpenCode source is needed
to attribute serialization to a particular client/provider transformation. The
catalog, exported MCP input types and observed outcomes alone establish behavior,
not model-versus-client causation. No product-parity, heldout quality, production
deployment or general worst-case correctness claim follows from this campaign.
