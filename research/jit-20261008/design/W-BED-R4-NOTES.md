## 2. The task

A fictional group ("Hollin ...") closes a month. It has K subsidiaries: 2, 3, 4 or 6 for d2–d5. Each subsidiary's
month-end pack is a complete earlier-rung task, generated by that rung's own `generate()` at a derived child seed:
- a receivables close (W-bed R1);
- from d3, ceil(K/4) of them are a supplier statement audit (W-bed R3).

The parent must:
1. report each pack's result unchanged, scored by its own rung's oracle;
2. translate:
   - each pack's external balance (R1 `totals.open_usd_cents`; R3 adjusted balances, summed per currency) at the
     stated closing rate;
   - each subsidiary's intercompany schedule (per currency, then translated once) at the consolidation-date rate;
3. pair intercompany items. A pair is X's receivable against Y and Y's payable against X with the same currency, the
   same amount, and memos describing the same charge for the same period;
4. eliminate each pair at the receivable's translated amount;
5. report consolidated receivables and payables.

What makes it harder at each step of d:
- From d3, one pack in three or four prints one billing system's dates in a dialect no R1 task uses, which is the
  composition test.
- From d4, the rate table is dated: each pack is translated at its own reporting date.
- At d5, JPY schedules and a CHF group currency are possible.

Output is `{group_currency, subsidiaries[{sub_id, pack, report, 4 balances}], eliminations[], consolidated{}}`. The
oracle is exact.

## 3. Oracle composition

The end-to-end oracle is `scoreGroup`. It passes only if all of these hold:
- every pack report passes its own rung's oracle, recomputed from the child seed (`childOracle`; a test checks it
  equals the R1/R3 bed oracle);
- the four translated balances of every subsidiary are exact;
- the elimination multiset (pairs and amounts, any order) is exact;
- the consolidated block is exact;
- the group currency is right;
- every subsidiary appears exactly once.

`composedOracle(task, trace)` is the AND of three parts:
1. **each child's composed oracle**, i.e. its own rung's stages and relations on the child trace. A planted pack is
   checked against its re-rendered inputs;
2. **the parent stage oracles**:
   - `children`: child oracles;
   - `translate`: intercompany side exact;
   - `pair`: set-exact;
   - `eliminate`: local to the pair hand-off;
   - `report`: local checks (`reportLocal`);
3. **the relations**:
   - **W1 pack carried**: the report's pack output equals the child trace's final result;
   - **W2 pack translation**: external balances are the stated translation of the pack output, and the report
     carries the translate hand-off;
   - **W3 eliminations carried**: the report's eliminations are the eliminate hand-off;
   - **W4 group conservation**: gross minus eliminated equals consolidated on both sides, and `eliminated_minor` is
     that amount.

The tests check that `composedOracle` agrees with the end-to-end oracle on the reference trace and on every control's
trace, at every difficulty, on 20 seeds [M]. The analyst side also gets the mined invariants G1–G3 plus W1–W4.

## 5. Child-seed derivation

```
childSeedOf(parentSeed p, difficulty d, slot k) = 1,000,000 + 64·p + 16·(d − 2) + k      (k in 0..15, d in 2..5)
```

- The child keeps the parent's split.
- Its difficulty is clamp(d, 3, 4): d3 for parents at d2–d3, d4 for parents at d4–d5. Those are the difficulties the
  R1/R3 streams run (W-BED §2.5).
- The map is injective because (d − 2, k) fills 64 slots per parent.
- Every child seed is ≥ 1,000,000. The largest bounded `to` in `SEED-LEDGER.json` is 8,524, so child seeds stay
  outside every reserved range.
- One ledger row is open-ended: `test-clean` (test split, 7200..∞, status `clean`). Children of held-out parents fall
  inside it. That row marks clean held-out territory; it is not a reservation that a child seed would collide with.
- Held-out parents (≥ 7001) therefore get held-out-split children far above any dev range.
- The test checks 11,904 seeds (dev parents 301–390 and held-out parents 8201–8224, 8301–8324, 8401–8424, 8501–8524;
  d2–d5; all 16 slots): all are injective,
  ≥ 1e6 and outside every bounded range [M].
- Example: dev parent 301 at d5 gets children 1,019,312 to 1,019,317.

## 6. The outside-profile plant

**What it is.** A new dialect is added to `lib/dialects.mjs`: `JULIAN_CYYDDD`, an IBM-style Julian date. C is the
century offset from 1900, then YY, then the day of the year, so `125032` is 1 February 2025. No R1 or R3 style prints
it (tested), and it round-trips.

**How it is planted.**
- The planted R1 pack is an ordinary R1 task.
- In it, one billing system's invoice-list dates are re-rendered in CYYDDD.
- That system's sentence in the R1 notes is rewritten to explain the format.

**Which systems qualify.** BRIGHTDESK, LEDGR and KOBO, chosen in seeded order. A system is plantable only if both
hold:
- it has at least 4 invoices in the pack;
- the misread pipeline (the R1 solver ignoring the close date for that system) fails the R1 oracle.

So reusing the R1 solver raw on a planted pack is wrong by construction, not just unusual.

Planted systems over seeds 301–310 (one plant at d3 and d4, two at d5): LEDGR 22, BRIGHTDESK 14, KOBO 4 [M].

**Hidden truth.** `childrenOf(task)` gives each pack's sub id, rung, child seed, split, difficulty, `outsideProfile`
and `{system}`. `childTask(task, id)` returns the planted child task with its re-rendered inputs. The child's own
oracle is unchanged, because a date dialect does not change the answer.

**VERITAS is excluded.** Its dates sit inside JSON-lines strings, and the slice-1 profile does not see them: a
planted VERITAS pack was refused in only 21 of 24 cases [M]. This is a profile blind spot; see §9 item 3.

**Composition test (measured with slice-1 `profile.mjs`, read-only).**
- The R1 profile was learned on the R1 stream shape: dev 301–316 at d3 plus 317–324 at d4.
- It was checked on the R1 packs of parents dev 341–346 at d2–d5.

| packs | refused as `novel` |
|---|---|
| planted | **24/24**, each naming `inputs.invoices.<planted system>` |
| unplanted, child d3 | 5/18 (false alarms) |
| unplanted, child d4 | 13/24 (false alarms) |

An earlier probe on parents 341–350 refused 23/40 unplanted d4 packs, or 20/40 with the size features ignored. The
reasons given were line-format, line-family, string-length, missing-path, line-count and vocabulary (flag words) [M].

Read: the profile catches the plant, but at its current thresholds about a third of in-profile d3 packs and about half
of d4 packs would be missed reuse. This is the first thing R4 will show in a real run [I].

Before the clamp, children at d2 were outside the R1-stream profile on 20/20 packs. That is why child difficulty is
clamped to 3..4.

Amount-only pairing fails the elimination set on 20/20 tasks at every difficulty, and so does memo-only (tested). Two
kinds of decoy cause this:
- **sibling decoys**: a flat fee, re-billed for the previous period, at the same amount, which the buyer has not
  booked;
- **cross decoys**: two one-sided items of different charges at the same amount.

Disputed items (the buyer booked 85–97% of the amount) defeat memo-only pairing. Buyer memos quote the seller's
invoice number 80%, 40%, 20% and 0% of the time at d2–d5, so the judge has to read the charge and period at higher
difficulty.

**Runtime** at d5: generate about 0.6 s cold (both the children and the group layer), oracle 7–24 ms [M].

## 9. Deviations from W-BED.md, and why

1. **Plant rate.** W-BED says 1 subsidiary in 6. Here it is 1 of 3 at d3, 1 of 4 at d4 and 2 of 6 at d5. At 1 in 6, a
   d3 or d4 task would usually have no plant, and the composition test needs one per task to be decisive per task.
2. **K at d2 and d4.** W-BED gives only K = 3 at d3 and K = 6 at d5. Here K = 2 at d2 and K = 4 at d4, following the
   drift knob.
3. **R3 count = ceil(K/4)** from d3: 1, 1, 2 packs. W-BED says "1 in 4"; rounding up guarantees at least one R3 pack
   from d3.
4. **Child difficulty clamped to 3..4.** W-BED leaves it open. At d2, children fall outside the R1-stream profile on
   20/20 packs, so every pack would be "outside-profile" and reuse could not be measured. At d5, R1/R3 streams never
   run d5.
5. **What is consolidated.** The group consolidates two things:
   - receivables, from R1's `open_usd_cents`;
   - payables, from R3's adjusted balances.

   Intercompany items are a parent-level schedule per subsidiary. They are not embedded in the child data, so every
   child stays byte-identical to its rung's `generate()` (tested) and its oracle needs no change.
6. **Pairing rule.** Pairing requires exact amounts, and disputed amounts are not paired. That makes the elimination
   set exact. W-BED's "judge on memo text plus amount matching" becomes: candidates by amount, then a judge on the
   memos.
7. **The outside-profile control models the misreading as ignoring the close date** for the planted system's
   invoices. It is the cleanest misreading that provably changes the R1 answer. A real solver might misparse instead.
8. **VERITAS is not plantable** (§6): the slice-1 profile is blind inside JSON-lines strings.
9. **The `test-clean` ledger row is excepted** in the child-seed check (§5).
10. **No necessity attack.** This follows W-BED §2.4 item 3. The triviality table lists r4 with necessity "none by
    design".
11. **Inline sizes are far above W-BED's implied scale.** "3–6 R1-sized subproblems" is about 14K tokens each at d3,
    but R1/R3 at child d4 are 23–39K each, so d5 is about 150K. The Haiku-agent estimate in W-BED §3.4 is probably low
    at d5 [I].
12. **`scoreReuse` gets its truth by construction**, from `outsideProfile` in the hidden truth. Host `classifyReuse`
    gets it counterfactually, through `calleeWouldPass`. For planted packs the two agree by construction, because the
    misread fails. For unplanted packs they agree as long as the callee is correct [I].

## 10. What arm (c) and the JIT arm need from flow-v3 that slice 1 does not provide

1. **A per-call task prompt.** The host builds the child task as `{prompt: contract.taskTemplate, inputs: req.input}`
   (`call-host.mjs` line 255), with a fixed template per registry entry.
   - An R1 child's own prompt varies per task. The parent passes `{pack, prompt, inputs}` per subsidiary, but only
     `inputs` reaches the child.
   - R1's close date is also in `ledger_spec`, so the R1 reference should not depend on the prompt. That needs
     checking when the arm (c) R1 reference is frozen.
   - Needed: either `flow.call(hash, input, {prompt})`, or a rule that every rung's reference reads only `inputs`.
2. **A fallback for a refused child.** `interpret-child` and local deopt are slice 2, and there is no agent node.
   - Today a refused pack can be handled in only three ways:
     - (a) solved in the parent's own compiled code, which is re-derivation and the expensive path;
     - (b) the whole task deopts;
     - (c) a parent-side adapter rewrites CYYDDD to ISO and calls again. The bed scores this as `adapted` if the
       output passes.
   - Arm (c)'s outline says "solve that pack without the library solver". Without an interpret-child or agent node,
     that means arm (c) carries its own R1 solver, which defeats the point.
   - Needed: `onRefuse: 'interpret'` (slice 2), or the adapter pattern written into the reference.
3. **A profile that sees values inside JSON-lines strings.** VERITAS planted dates are missed: 21/24 refused. Needed:
   per-field features for JSON-lines lines in `profile.mjs`. Until then, the bed plants only line-text systems.
4. **Profile thresholds or `ignore` options at the host.**
   - `checkProfile` is called with defaults. The host takes no `ignore` and no per-entry check options.
   - Measured false alarms on in-profile packs: 5/18 at d3 and 13/24 at d4. That would read as roughly 30–55% missed
     reuse.
   - Needed:
     - per-entry check options in the registry (for example `ignore: SIZE_FEATURES`, and line-format tolerance);
     - or a profile learned on the whole stream, not only on accepted traces;
     - and, either way, a decision before the paid run on whether `novel` refuses or only warns.
5. **Budget under `map`.**
   - Each child call reserves its `budgetUsd`, and the reservation must be strictly below the parent's remaining
     budget (line 267).
   - At d5 a parent maps 6 child calls. With reservations held concurrently, the parent's `perTaskUsd` must exceed
     Σ child budgets plus its own judges.
   - Needed: a stream rule `perTaskUsd(R4) ≥ K × childBudget + parent margin`, or sequential calls in the reference.
     The current per-rung caps have not been sized for this [I].
6. **Attributing events to subsidiaries.**
   - `scoreReuse` needs `childId` for each host event.
   - The host event carries `path` (`.../call:<name>#n`) and `inputDigest`.
   - The bed exports `packDigestOf(inputs)` = sha256(canonical(inputs)). That equals `inputDigestOf` for plain JSON,
     so raw packs can be matched by digest and adapted packs by name.
   - Needed: the reference and the compile prompt (v5, §4 of SLICE1) should require `name: <sub_id>`, and
     `stream.mjs` should write the span name as `childId` in `calls.jsonl`.
7. **Stream wiring** (FLOW-V3-SLICE1 §3, items 1–5):
   - prompt version 5 with the `flow.call` block;
   - `FLOW_TOOL_V3` in compile;
   - `run-compiled` ledger hand-off and `flow-scope.json`;
   - the `services.mjs` `/call` route;
   - a per-arm registry with CUR kept / ISO wiped, registering accepted versions with `learnProfile`.

   None of this exists yet, and each item is an engine change for the E2 freeze. Arm (c) needs items 1–4 of that
   list; the JIT arm needs all of them.
8. **Call depth.** The R3 reference is itself expected to call R1 parsers, so R4 reaches depth 2. That is under the
   default `maxDepth` 3, but arm (c) for R3 must be registered before R4's, and the R3 entry's own profile then
   governs those nested calls.
9. **Missed reuse that never reaches the host.** If the parent re-derives a pack inline, there is no event, and
   `scoreReuse` counts it as `rederived` only because the bed knows every pack has a library solver. A JIT run whose
   library lacks the R3 solver (ISO) must pass `library` without `wbed-r3` so that this is not counted against it.
   Needed: `stream.mjs` should pass the arm's actual library to `scoreReuse`.

## 11. Open questions

- Arm (c) reference: an adapter for CYYDDD, or refuse and re-derive? This choice sets the "correct" construction-cost
