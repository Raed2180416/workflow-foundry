## Agent result 1

I wrote `/home/user/workflow-foundry/research/kev-20261007/JUDGE-PROGRAM.md`. It covers all ten required sections plus a risks section and an appendix of what I measured. Nothing was trained, served or sent to a hosted model, no sealed bed or test split was read, and no git state was touched.

**Is 5K sufficient?** Probably not for the hard ports, and the program measures it rather than assumes it.
- Wave 1 has 13 ports, so 5K rows gives each hard port about 480 rows. Kev's own docs saw no detectable gain at 400 records and +5.9 pp at 1,050.
- Written prediction: 5K is enough for the three template-bound records ports (status meaning, sign convention, timestamp re-stamp) and not enough for the hard ports. About 20K rows (about 1.75 h at the smoke rate) is the first size expected to move them.
- Test: nested runs at 2.5K, 5K, 10K and 20K, with 40K only if the curve justifies it. 5K counts as sufficient for a port if the 20K gain on held-out data has a 95% upper bound under 2 pp.

**What limits robustness is text variety, not row count.**
- Measured on 900 dev worlds of the records bed: only 32 distinct sign-convention sentences, 44 date-order ones, 220 timestamp ones and 288 status-meaning ones.
- The other beds have 4–9 injection templates each.
- A fine-tuned model will memorise these, so accuracy on new seeds from the same templates only shows recall. Promotion therefore depends on held-out paraphrases, held-out templates, held-out beds and real traces. New-wording test pools are written by a separate worker.

**Other findings that change the plan:**
- **The 0.287 s/example figure comes from the laptop smoke run on about 64 toy records.** Foundry rows are 60–600 tokens, so the first laptop job re-measures speed and memory at 300, 2K and 8K tokens before anything else.
- **The bridge's training job defaults `maxState` to 384**, and Kev silently drops longer records. Every job sets it explicitly, and acceptance requires zero dropped records.
- **The bridge's benchmark job cannot run Kev's suites directly or set the temperature.** Forgetting is measured by uploading the suite files as data, and the temperature is refit in the cloud.
- **Two decisions the inventory rated high fit a lookup table.** "What kind of notice is this" and "which venue tier" are named outright by the document's rendered type field, so I excluded them.
- **The probe's failure-class data is solved by keywords** (rule accuracy 0.971), so it is training data only. The probe has finished only its rule arm; stock Kev and Sonnet are still running.

**Scope:** 40 ports covering 46 of the inventory's decisions, 18 deferred and 36 excluded or handled elsewhere (100 in total), each mapped with its reason. The 13 wave-1 ports include the three decision types the C4 claim names: whether a kept workflow applies, drift, and failure class. They also include the gate that lets Haiku's extractions escalate to Sonnet only where Kev flags them.

**Owner decisions needed:**
- **Haiku arm.** An earlier probe note records "owner request: no Haiku arm", while this program's direction makes Haiku the weak model to improve. I kept Haiku and Sonnet arms; the owner should confirm.
- **Policy entries.** Kev runs need entries in `policy/models.json`, which is the only allowed source of model ids.
- **Hosted budget.** About $150 for wave 1.
