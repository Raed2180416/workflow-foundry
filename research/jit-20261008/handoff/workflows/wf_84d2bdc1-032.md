I've written the auto-heal design and ran a $0 replay probe that tests its core mechanism. On the frozen runtime, replay plus a single substituted node output found the root cause of all three failures. It also flagged the same weak spots on runs that passed only by luck, with no oracle needed. **How the loop works.** It is offline and runs in this order:
- **Detect:** collects signals from recorded runs.
- **Classify:** first checks that the run replays exactly, then sorts out environment faults, impossible contracts, escalations that worked as designed, and model variance.
- **Localise:** replays the run from the journal, substitutes one node's output at a time, and re-runs downstream code to rank suspect nodes.
- **Propose:** a model turns typed facts into typed patch operations; Haiku 5.5 first, then Sonnet, then Opus.
- **Verify:** stages V0–V8, all in code.
- **Promote:** a pure code function with compare-and-swap and rollback.
- **Learn:** turns the pattern into a lint rule, template change or probe for the constructor.

The model only proposes. Code applies patches, runs every gate, and promotes or rolls back. This is the roadmap's C3 pipeline and its R-16 "edits as replay-proven proposals".

**Probe results ($0, strict replay, no model called)**
- **The kit is the right runtime.** All 87 frozen-kit files (`src/`, `schemas/`, `policy/`, `skills/`, `bin/`) match commit 880c6b9 exactly, and the model policy is identical. The live `src/` already differed in 11 of those files and had 4 new ones.
- **Replay is exact.** All 16 recorded C0 F-haiku trials replay exactly: same task hash, oracle score, run verdict and call count. That includes 11 passing trials whose workspaces had been deleted. The P1 failure also replays exactly, at 2–9 s per run.

  - A substituted node must keep the inputs the original read. Otherwise the downstream prompt changes and replay misses; this happened 4/4 before the fix.
  - Replay keys don't include the node id, so k-sample siblings with identical prompts would replay one sample twice. Each sibling gets a distinct reader tag. This one comes from reading the code, not from a run.
- **Pinned lint.** The strict lint and verdict files, pinned at `13f7664` and run on the kit's modules, reproduce the existing lint audit exactly.

**Patches and gates**
- **Patch operations are a closed set:**
  - add an evidence field with a check;
  - k-sample agreement;
  - escalate the model class;
  - add, tighten or relax a check (relaxing needs a quoted contract justification plus a mutant proof);
  - fix a code node from a failing assertion;
  - edit instructions;
  - add a probe;
  - mechanical fixes for lint errors.
- **Forbidden:** there is no operation for deleting a check or node, weakening acceptance, or declassifying labels, and the verifier rejects them in any form.
- **Version-bound:** each proposal is tied to its base workflow, kit, lint version and model policy, with lineage, and changes one locus.
- **Lint debt first:** all three base workflows fail the strict lint because their acceptance only checks that an answer exists. Mechanical fixes for those errors go first.
- **Verification gates, cheapest first:**
  - static checks, a literal-leak scan and strict lint;
  - an acceptance-weakening rule;
  - the failing case passes 3 times, with changed nodes called live;
  - every previously passing recorded run still passes, with unchanged nodes replayed;
  - acceptance still rejects the bed's known-bad answers;
  - cost and latency within 1.25× of the original;
  - 12 fresh dev seeds × 2, run paired against the original and stratified so a hard-coded value fails;
  - grader files unchanged.

**Promotion.** A promoted version runs alongside its parent and rolls back automatically on a circuit breaker. It never touches frozen artifacts or pre-registered experiment arms. Relaxing a check, raising a node to Opus, or adding more than 25% cost goes to owner review instead.

**Lessons for the constructor.** Each case produces one, stored as a reviewed proposal and applied only through a new kit hash:
- **Records:** a fragile, unguarded global read becomes a lint error, plus a rule that construction probes must exercise each value of a global setting.
- **Codefix:** a lint warning for a heuristic check that can route a correct answer to a replacement step, plus a self-test that documented-legal changes pass.
- **P1:** a lint warning for a check branch that lets the model exempt itself from checking the field that matters.

**Limits**
- Nothing heals without a detection signal.
- Without an oracle a heal may only add guards, and those runs stay `unverified`.
- These three cases are already-inspected development data. They prove the plumbing, not the fix rate; that comes from the extended EX1 experiment.

**Cost.** About $10–14 to heal all three cases end to end, mostly the fresh-task gate. That fits EX1's $15–30 budget. The build is about 1,500–2,000 lines plus tests under `experiments/heal/`.

**Owner decisions** (none blocks the free first steps):
1. **Auto-promotion scope.** Guard-adding patches promote automatically, while relaxations, Opus and over-25% cost increases go to review. Default: yes.
2. **"One node" in R-16.** Read it as one locus, so identical clone nodes count as one; codefix's `check1`/`check2` need this. Default: yes.
3. **Shadow period.** Run 10 shadow tasks per promotion, about $3, under the heal budget. Default: yes.
4. **When lessons reach the builder.** Fold them in only after EX1, so CX3 and EX1 don't run on a changing kit. Default: after EX1.
