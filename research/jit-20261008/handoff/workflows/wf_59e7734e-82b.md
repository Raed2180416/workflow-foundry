## How it works
- **Acceptance grade.** A presence test (`exists X`, `ne X null`, `gt X.length 0`, comparing a value with itself) is not a gate. `exists nodes.check.pass` is also not a gate, because `pass:false` still satisfies it. A gate is a strong acceptance predicate, a strong `assert`, or a gating verify the answer depends on. A `same-model` verify never counts as independent.
- **No-oracle mode.** `oracle: {mode:"none", reason}` clears the existence-only error. Runs then end `unverified` with code `NO_ORACLE_DECLARED`.
- **Verdict for a succeeded run.**
  - `VERIFY_FAILED_NONBLOCKING`: a `gate:false` verify that nothing reads recorded `pass:false`. This is my reading of "needs-review"; there is no separate verdict value for it.
  - `ERROR_COLLECTED`: a collecting map's failed count is not gated and items failed.
  - `ACCEPTANCE_EXISTENCE_ONLY`, `NO_ORACLE_DECLARED`, or `ACCEPTANCE_UNASSESSED` when the workflow is not supplied.
  - Otherwise `pass`.
  - A failing gating verify still stops the run as `inconclusive`.
- **Lint codes.** Each finding carries `code`, `severity`, `path`, `node`, `repair.action` and `repair.hint`.
  - Errors: `ACCEPTANCE_EXISTENCE_ONLY`, `VERIFY_NOT_GATING`, `ERROR_COLLECTION`.
  - Warnings: `ESCALATION_WITHOUT_CHECKS`, `GLOBAL_READ_UNGUARDED`, `CLASS_ABOVE_DEFAULT_UNJUSTIFIED`, `NO_ORACLE_DECLARED`, `ORACLE_DECLARATION_REDUNDANT`, `LINT_RULE_SKIPPED`.
- **Fail closed.** A malformed workflow grades `unassessed`, never `pass`, and neither the lint nor the verdict throws. I checked this by fuzzing 1,200 mutated artifacts.

## Defects found and fixed

**P1, authority bypasses (the runtime trusted an editable run record):**

1. **Approvals.** High-risk effects were gated on the run record's `approvals[id].status`, not on the chain. Flipping a pending approval to "approved" in the record, or planting one ahead of time (the approval id is predictable), made the effect run with a `pass` verdict, and `verify-run` reported nothing.
   - Fix: an approval now counts only if the chain holds the user's `approval.decided` after the matching `approval.requested`; otherwise the run fails with `APPROVAL_TAMPERED`.
   - `approve()` now refuses a pending record whose tool, arguments or taint labels differ from the chain's request. Otherwise the approver could be shown harmless arguments for a harmful request.
   - `verify-run` now cross-checks approvals: `APPROVAL_EDITED`, `APPROVAL_UNBOUND`, `APPROVAL_MISSING`.
2. **Run identity on resume.** Resume compared only the engine and model-policy hashes with the birth event. Editing `run.policy.allowedCapabilities` in a paused run let a capability that was never allowed run.
   - Fix: resume now compares workflow, input, policy, registry and model binding with the birth event and refuses with `RUN_BINDING_CORRUPT`. This check is shared with `verify-run` as `identityChanges()` in `audit.mjs`.
3. **Human answers on resume.** An answer written into the record with no `human.answered` event was used downstream. Fix: resume now refuses with `CHECKPOINT_TAMPERED`.

**P1, tampering that verified clean:**

4. **Events appended after a run closed.** Adding a second seal plus edited outputs and verdict to a closed run verified clean, even against an anchor taken at the close (an append isn't a rewrite).
   - Fix: after the closing seal, only its terminal event and later annotations are allowed. Anything else is `RUN_EXTENDED`; a decision bound late is a warning, a transcript bound late is info.
   - The closing seal is now the one checked against the verdict and its inputs.
   - Replay ignores anything a source run's chain gained after it closed.
5. **Planted journal rows.** A forged row inserted under a run while it was paused got covered by that run's later seal. Replay then served it as verified (`check: 'sealed'`), and both runs verified clean.
   - Fix: a row that is only sealed, never charged by an event, is now served as unverified (`REPLAY_UNVERIFIED`; an error under `--require-bound`).
   - The source run gets `JOURNAL_ROW_UNREFERENCED`.
6. **`--journal` override.** Passing a pristine copy as `--journal` hid an edited workspace journal. Fix: it is now honoured only for runs whose birth event says the journal is external; otherwise `JOURNAL_ARGUMENT_IGNORED`.

**P2:**

## Defects found and fixed

**P1, cancel left processes running (existed before the scheduler).**
- **What happened:** `foundry run`, `resume`, `tick` and `trial` had no signal handler. Sandboxed code (and model-CLI subprocesses) run in detached process groups, and the sandbox's time limit is a timer inside the CLI process. When the CLI died on SIGINT or SIGTERM, the sandbox was reparented to init and kept running.
- **How I confirmed it:** a 60-second busy loop was still running 10 s after Ctrl-C. The sandbox sets no CPU-time limit, so an infinite loop would run forever.
- **Fix, in `bin/foundry.mjs`:** on SIGINT or SIGTERM these four commands abort every run they own. The abort reaches each node synchronously, which SIGKILLs the sandbox process groups. The CLI then writes `{interrupted, runs, resumable}` to stderr and exits 130 or 143.
- **Ctrl-C still behaves like a crash otherwise:** the run stays `running`, has no stop or verdict event, and can be continued with `foundry resume`.
- **Test:** new `tests/cli-interrupt.test.mjs` (2 tests). They fail against the old CLI and pass now.
- **Docs:** one paragraph added to the Scheduling section of `docs/ARCHITECTURE.md`.
