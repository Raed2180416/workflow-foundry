# AMP interface map (2026-10-06, read-only inspection)

## Summary
AMP (product name; the service is "Hippocampus") is a local-first, single-writer memory and context authority for coding agents (Codex, Claude Code, OpenCode, Cursor, ARC/CLIDE). It is a Rust daemon (crates/hippocampusd, about 54k lines; crates/hippocampus-core, about 45k lines) plus a Python client/MCP server (clients/python) and an OpenCode plugin. Integration branch: codex/amp at 6df3056355 (2026-10-04). Agents reach it over a loopback HTTP API (/v2/*, roughly 100 routes) authenticated by endpoint.json plus a token file, or through an MCP server (mcp==2.2.0, roughly 70 to 87 amp_* tools). Its core is a turn-time context compiler (/v2/context/compile) that returns a bounded packet with provenance and a receipt. Around it sit: immutable commands, workspace capsules (dirty and non-Git), typed claims, a support graph, goals and intent reconciliation, active plan graphs, work contracts, task attempts (begin, report, assess, deliver), Experience outcomes and Pattern proposals (learning), Dream synthesis jobs, evidence-acquisition loops, language indexes, and Jev (TypeSafe) typed evaluation as an optional shadow selector.

Maturity is low and the docs say so plainly. CURRENT-STATE says 0/72 cognition obligations are accepted, and the recent comparisons are negative K=1 runs with no lift shown. Context compile latency runs from about 2.6 s (optimized build) to about 19 s (dev build), against a 30 s MCP deadline and a 3 s hook deadline. Internal synthesis has produced zero proposals so far because of provider failures. The documented next task is to qualify the optimized daemon through the ordinary installer and a real MCP call, then do same-install correction from real feedback, then actor-authored learning and A-to-B transfer, then the Jev consumer and a deterministic-vs-Jev comparison. Worktrees dated today (2026-10-06) also contain work not yet integrated: an intent card and requirement ledger, a Claude Code Stop-hook verifier v2, a measured Claude Code default, and scale work. So CURRENT-STATE already lags.

Boundary: the contract says AMP does not own planning, delegation, reasoning-operator selection or external effects (HP-BACKBONE-04). ARC keeps authority over intent, actions, effects and completion (HP-AUTH-02). AMP must remain the only memory writer, with no fallback stores (HP-AUTH-01). That leaves workflow orchestration and routing open for Foundry, but any Foundry memory, trace or learning store would breach AMP's single-writer rule unless it writes through AMP.

Main seams: Foundry nodes call compile_context with task, obligations and session. Runs map onto work contracts and plan items, and iterations map onto task attempts with frozen acceptance specs. Outcomes go out as Experience records, and reusable workflows are proposed as Patterns with a prediction and a falsifier. Audit uses /v2/context/compile/trace and the attempt history. The "arc" connector profile already exists.

Overlap risks: AMP's active plans, attempt loops, evidence-acquisition loops, Dream jobs, the verifier gate, Patterns/skills, Jev selection and semantic-provider selection could each become a second workflow engine, router, verifier, or learning store alongside Foundry's.
