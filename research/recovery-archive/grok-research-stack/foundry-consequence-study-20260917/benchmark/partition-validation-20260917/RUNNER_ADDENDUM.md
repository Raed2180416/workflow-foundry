# Runner correction before candidate exposure

Prime's source review found that `run.mjs` used `result.workspace/artifacts/...`, while native result.workspace is the workspace root and the Store directory is `workspace/.foundry`. The original runner would incorrectly fail its independent manifest check. No workflow had been read or executed when this defect was reported.

The original `run.mjs`, `FREEZE.json`, `SUITE.json`, `EXPECTATIONS.json`, and all other frozen files remain unchanged. `run-v2.mjs` uses `runner-replay.mjs` to resolve `workspace/.foundry/artifacts/<runId>/manifest.json`. A supplied filesystem fixture includes different manifests at the correct path and the original erroneous path, so the test distinguishes them by actual file contents. These are supplied path fixtures, not workflow executions or model candidates.

The permitted v2 source was reread at lines 156-262 and 287-331. Attempts expose `sampleId`, `instrument`, `valid`, and `completedSequence` at lines 195-199. Publications expose `startedSequence` and `completedSequence` at lines 227-228. Its all-status diagnostic at lines 241-262 compares every required attempt's validated completion strictly before each publication's start. Invalid, missing, or duplicate attempts count as incomplete. A missing publication fails even for an empty batch. The corrected runner uses those same field names and preserves the original non-gating status of this diagnostic. Supplied interval tests cover before/equal/overlapping fences, invalid/missing/duplicate attempts, and empty batches.

`runner-addendum.mjs` verifies the original freeze, runs syntax and fixture tests, and writes `RUNNER_TESTS.json` plus the exclusive `RUNNER_ADDENDUM.json`. The addendum binds the original freeze, original runner, unchanged suite and expectations, corrected source, tests, explanation, and supplied fixture bytes. Both freezes are verified before candidate access and after evaluation. Receipts identify both freeze hashes.

The approved command is now `node run-v2.mjs primary /exact/prime-supplied-workflow.json`. The original 98 primary plus 98 counterpart reservation remains shared across runner versions, using the same exclusive execution receipt paths. MaxSteps stays 160. The counterpart still requires later explicit supply by prime. No candidate exposure, native workflow execution, or budget reservation is part of this addendum preparation.
