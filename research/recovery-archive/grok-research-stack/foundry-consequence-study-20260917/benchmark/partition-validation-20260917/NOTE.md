# Independent finite partition validation

Worker 7 owns this new directory only. Construction uses the documented semantics in `../contract.mjs` and `../PUBLIC.json`, and the public fixture/evaluation interfaces in `../oracle-v2.mjs`. No model candidate, builder packet, prior suite/result, or `oracle.mjs` implementation was inspected to author this suite. Applicable `AGENTS.md` paths in the project ancestry were checked and none existed. Native `validateSuite` and `validateData` are used as generic public schema validators; their classification logic is not an expectation source. Wrapper validation exposed the required `schemaVersion: "1.0"`, `statuses`, and `checks` fields before the suite was frozen.

`expectations.mjs` directly implements these decisions: a thrown screening error yields error; an unusable screening observation yields inconclusive; a matching boolean false screen yields clear; a matching boolean true screen requires exactly one reproduction. A reproduction error yields error. A returned reproduction is complete only when identity matches, independence is true, evidence is a nonempty string, and reproduced is a boolean (with ok true). Complete positive means confirmed, complete negative means not_reproduced, and every other valid return means inconclusive. Claims are never inspected. Required attempt sets and synthetic work costs are derived alongside the manifest. The native legacy expectation helper is not imported or called for construction or preflight.

## Frozen coverage

The suite has exactly 98 executions per supplied workflow, with 98 reserved for a later prime-supplied faulty counterpart: 196 in total, below the 200-case cap. No candidate runs occur in construction or preflight. Every case uses the native budget unchanged, including maxSteps 160. There is no automatic retry or enlarged budget.

The 54 singleton reproduction cells cross independent absent/false/true, evidenceId absent/empty/nonempty, reproduced absent/false/true, and matched/wrong reproduction identity. Screening is usable and positive in every tensor cell. The expected tensor counts are one confirmed, one not_reproduced, and 52 inconclusive. These counts are checked from the axis table independently of the fixture builder's generated manifest.

Eighteen screening contrasts cross six non-triggering screening conditions (absent or false with matching identity; absent, false, or true with wrong identity; and a screening throw) with three unused reproduction possibilities (complete positive, incomplete, or thrown error). Reproduction must not be attempted in any of these cases. A separate usable positive screen followed by a reproduction throw checks the required failed attempt. Two additional cases treat a single whitespace character as a nonempty evidence string, with both reproduction booleans.

Five cases cover an empty batch and batch lengths two through five; the singleton cases cover length one. Four permutations of a fixed six-sample batch test preserved input order and failure isolation. Six homogeneous six-sample stress cases cover complete positive, complete negative, incomplete reproduction, clear screening, screening errors, and reproduction errors. All six positive screens must fit the original native maxSteps budget or the candidate fails that case; this protocol does not change the budget to make a candidate pass.

Eight runs have byte-identical six-sample inputs. Six rotations make each ID take each of the five dispositions across observations. A seventh changes only misleading claim strings and must preserve the first manifest; an eighth supplies complete positive evidence for all six samples. IDs and evidence tokens are freshly generated opaque hash strings from this study's fixed namespace. Input IDs do not encode a diagnosis. A different set of four cases changes input order while holding each ID's evidence fixed. Observation-table insertion order is reversed from input order.

## Evaluation and publication diagnostic

`freeze.mjs` writes the suite, expected outputs, partition index, and preflight receipt exclusively, then hashes these files, all authored sources, this note, and the three public interface files into `FREEZE.json`. `READY.json` records the freeze and zero candidate executions. These files must remain immutable after READY.

After prime supplies an exact workflow JSON path, execute `node run.mjs primary /exact/supplied/workflow.json`. The runner verifies the freeze before reading that candidate and reserves 98 cases in a new immutable receipt. It calls native `evaluateCandidate` from v2 with its default freeze enforcement; v2 internally loads its frozen dependencies and uses its legacy helper for validation, but neither source nor old suite contents are used to revise this suite's expectations. The native v1 report, v2 report, case stores, artifacts, candidate bytes, and file bindings are preserved under the new primary directory. A counterpart is permitted only when prime supplies it later, using the counterpart label. Each label can be used once, and reservations are never reclaimed automatically.

The runner also reads the actual manifests and checks them against the independent expected manifests, compares required and observed instrument attempt multisets, and recomputes the all-status publication diagnostic using its own required attempt sets and v2's audited native intervals. Native v2's confirmed-before-publication rule remains a gate. Completion of every required instrument attempt before publication for every disposition is reported separately as a non-gating diagnostic. Agreement with that diagnostic is checked; a diagnostic failure is never silently promoted into a native policy violation or ignored in reporting.

## Claim and exclusions

A passing result would establish conformance on these 98 frozen fixtures, the full stated 54-cell singleton reproduction partition, and the specified finite order/evidence/claim contrasts. It would also report whether every required instrument attempt had completed before publication in each observed run. It would not prove that arbitrary graphs, inputs, identities, strings, combinations of six samples, schedules, or instrument implementations behave correctly. The suite is deterministic and designed; it is not a population sample, statistical confidence bound, or universal proof.

The returned schemas require ok:true, a string sampleId, and actual booleans when boolean fields are present. Malformed returns (ok:false, missing/nonstring identity, null observations, nonboolean suspicious/independent/reproduced, nonstring evidenceId, or extra properties) are therefore outside the native v2 fixture domain. They are not mislabeled as inconclusive candidate tests. Generic schema-only negative tests check selected malformed examples without executing a candidate. Wrong string identities and missing optional fields remain legal and are covered. IDs must be distinct within a batch and batches longer than six are outside the task. No exhaustive ID-boundary, Unicode, timeout, cancellation, storage-corruption, arbitrary interleaving, retry-policy, or adversarial-host test is claimed.

Finite evidence swaps constrain input-only lookup or constant output on these particular examples. Timing and correct content cannot establish general causal use: a sufficiently specialized implementation may still pass a finite suite. Broad qualification, external model quality, and real laboratory validity are outside this study.
