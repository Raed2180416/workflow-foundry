The actual integration is present at `outcome-campaign.mjs:125-131`: `WorkflowGenerator(outcomes.generationHost(), provider, ...)`, with `autoApply:false` and the development evaluator. These are provider-withheld finite regressions from an existing benchmark, not newly sampled holdout evidence or OS-enforced isolation.

Before promotion the campaign rechecks the frozen protocol. It explicitly calls `outcomes.apply`, executes the proposed candidate, supplies the actual run and independently read artifact to the v2 audit, compares the exact expected JSON, and requires a satisfied observation. It then verifies the original unsatisfied receipt and confirms the original run still has status `succeeded` (`outcome-campaign.mjs:152-166`). The final delivery deliberately retains `independentTaskVerified:false`; its linkage is useful without implying arbitrary task or deployment success.

V2's publication gate requires validated complete positive reproduction before publishing a confirmed row. Completion of *every* permitted instrument attempt before *every* publication is a separate non-gating diagnostic (`oracle-v2.mjs:241-262`). Temporal order and matching finite outputs do not prove causal use. The original wrong run happens to satisfy the stronger ordering, as independently checked here. A final report must retain this distinction.
