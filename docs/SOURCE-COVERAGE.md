Snapshot: 2026-09-13. This inventory aggregates existing public acquisition
manifests, public dossiers and portable source maps. It does not reopen the
private ARC audit, copy private material, run upstream checkouts or make model
calls. Repository-only provenance paths below are deliberately plain text: they
are not shipped with the private npm package.

## Inspection evidence and limits

The aggregation finds **152 distinct explicitly cited revision/path/line ranges
across 110 distinct files in 44 repositories**. This is a count of recorded
citations. A range can refer to a README, license declaration, prompt, interface,
schema, benchmark metadata or implementation. It does not imply the full file was
read, tested or correctly understood, and overlapping ranges are not a count of
unique lines. No percentage of fully deconstructed files can be inferred.

The counted sources are the existing software/browser dossier and its Markdown
and JSON evidence indexes, the science/robotics/healthcare dossier and its three
portable source maps, and the SRE/security dossier with its two portable source
notes. Pinned GitHub line URLs and structured software evidence entries are
deduplicated by repository, revision, path and range. Explicit SRE alias ranges
such as `H:holmes/main.py:163-189` are resolved through that dossier's repository
table. Unqualified continuation ranges are omitted rather than guessed. The
source hashes and exact citation origins are retained in the receipt.

Four acquired repositories have no matching revision/path/line citation in this
counted record: `anomalyco/opencode`, `langchain-ai/langchain-mcp-adapters`,
`modelcontextprotocol/servers` and `modelcontextprotocol/typescript-sdk`.
`research/dossiers/opencode-environment.md` explicitly describes installed-binary
behavior and public documentation rather than a source audit. Executing an SDK
package in a local integration test also does not establish that its separately
cloned source was deconstructed. These four therefore remain acquired, with
source-inspection depth unestablished by this inventory.

## License evidence

**46 repositories have at least one recorded license-related file; two do not:**
`emeraldsci/ecl-protos` and `horizon3ai/h3-cli`. There are **218 deduplicated
repository/path/hash license records**. Acquisition uses a filename heuristic and
retains at most 20 matches per repository. Six inventories hit that ceiling:
Datadog, LangChain, n8n, OpenAI plugins, OpenAI skills and the XBOW historical
benchmarks. Some filename matches are source files containing the word “license”
or “notice”, so 218 is not a count of license grants. The ledger also cannot prove
that all licenses in a repository were discovered.

The recorded domain reviews distinguish permissive roots, copyleft roots,
source-available frameworks, mixed document/skill licensing and component-specific
notices. They are observations, not a redistribution compatibility decision.
`research/dossiers/science-robotics-healthcare.md` records the ECL community
README's MIT badge versus the acquired Apache license text, and BioNeMo's code
versus documentation/skill terms. `research/dossiers/software-browser-skills.md`
records n8n's source-available/enterprise split, per-skill licenses in the OpenAI
catalogs, and restricted document-skill material in the Anthropic catalog.
`research/dossiers/sre-security.md` records component-specific terms within
Shannon, Datadog and benchmark payloads. These issues remain visible; no new
license was chosen and no upstream license or implementation was copied into the
product by this inventory.

Public pages, exported workflows, SDKs, protocol schemas and command-line adapters
do not expose the complete proprietary systems behind them. The dossiers preserve
this distinction for LILA, Skild, Hippocratic AI, Emerald's hosted lab execution,
Formant's backend, Rootly/Resolve services, Datadog Bits, NodeZero, XBOW, Torq,
Harvey and Hebbia. A historical primary paper or a vendor benchmark is evidence
of that publication's claims and version, not a replicated current service result.

This inventory establishes the recorded acquisition and selected inspection
coverage. Model performance, complete source deconstruction, deployment safety,
private-service internals and product parity need separate evidence. No such
claim follows from repository size, number of citations, or successful packaging.
