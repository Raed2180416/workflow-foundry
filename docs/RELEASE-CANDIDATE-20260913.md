## What is implemented

The **14 portable skills** cover the generic construction process, native runtime,
human steering, independent evaluation, component integration, seven broad
domains, and LangGraph/n8n lowering. References preserve their source provenance
without depending on uninstalled research directories.

The native engine executes typed task, assert, human, wait, map and loop nodes with
explicit dependencies, conditions, bounded attempts/concurrency/cost/time,
checkpointed state and verified event history. Host capability contracts own
effects, permissions and mandatory evidence. Skipped prerequisites cannot silently
authorize their dependent effects. Uncertain external outcomes remain uncertain.
Runs bind their workflow, capability registry and native engine identity.

The construction checker catches provably absent output paths and invalid nested
wrappers while preserving unknown/open schemas and conditional reachability.
Generic causal message-history rules and neutral multi-turn controls address the
observed query/action handoff failures. Static validity is not a task oracle.

Drafts can be tried before application without consuming their request or creating
a reusable head. Trial receipts bind the exact candidate, input, registry, policy,
events and artifacts. Failed applied runs can create bounded diagnostic repair
requests that retain original intent and version lineage. Exact delivery checks
reject an old proposal paired with a different version's successful run.

The visual editor inspects actual source-bound graphs, nested executions, requests,
proposals, failures, human questions and evidence. It supports natural-language
requests handled by a connected host agent or the explicit optional model bridge.
It does not fake model inference in browser JavaScript. Draft trial views have no
production run/approval controls. Input-rejected trials retain their exact graph
without invented execution. Provider quota errors pause automatic dispatch.

Project-scoped installation supports **OpenCode, Claude Code, Cursor, Codex and a
generic MCP configuration**, with portable skills and supported advisory hooks.
It checks conflicts and retains restoration journals. It does not modify global
settings, bypass client trust or sandbox the host agent's unrelated direct tools.

LangGraph's restricted serial profile was exercised against the actual pinned
Python/LangGraph runtime. Unsupported semantics are rejected. The n8n export's
generated code has local controls, but **no real n8n engine/import run** has been
established. Neither adapter silently promises native-runtime equivalence.

## Actual model evidence and what it does not establish

The research used actual OpenCode TUI sessions with observed free provider models,
including Big Pickle and Ling. **Haiku 4.5 was not tested.** Completed response
exports recorded zero cost; unavailable responses and infrastructure failures
were retained separately. These observations do not promise continuing free
availability or a fixed provider backend revision.

In the 55-case simulated incident campaign, the same skills-only generated
artifact scored **41/55 with default tools and 55/55 with mandatory host evidence
contracts**. A separately generated host-treatment artifact scored 55/55 under
those contracts and 34/55 under defaults. This isolates an enforcement benefit;
it does not show that the model learned better reasoning.

An actual installed-skills/MCP TUI produced and executed NumericRollup, yielding
`{count:3,total:21}`. Its complete integration receipt still failed because the
required final locator/inspection chain was incomplete. A later revision mixed an
old proposal with a new run; that receipt correctly failed too. Independent
zero-model replay of the unchanged candidate passed seven transport/artifact
controls. The new trial/repair/delivery APIs address those failures generically,
but their effectiveness with that model has not yet been measured.

The original mini-SWE DefaultAgent comparison used a frozen source/dependency
closure and two diagnostic task families. In the bucket task, the original agent
completed in three calls and passed 70/70 hidden checks. Generated code also passed
70/70 checks, but its third model call hit **HTTP 429 FreeUsageLimitError before
submission**, so its whole-task result remains provider-unavailable, not a win.
Both arms of the second task family hit the quota before environment actions.
There is no supported aggregate parity or noninferiority claim.

The separate live visual batch-generation attempt exhausted three revisions on

## Run locally

```sh
cd /home/raed/Projects/workflow-foundry
node bin/foundry.mjs doctor
node bin/foundry.mjs serve --workspace /path/to/an/existing/task-project --port 4177
```

To install into an existing project using OpenCode:

```sh
node /home/raed/Projects/workflow-foundry/bin/foundry.mjs install \
  --project /path/to/an/existing/task-project --client opencode
```

Use `--dry-run` to inspect the concrete changes. The installer returns the receipt
needed for restoration. Other client options are `claude`, `cursor`, `codex` and
`generic`; the generic configuration must be imported by its actual client.

Reproduce the local qualification with:

```sh
node research/qualify-release.mjs
```

That command deliberately requires all local opt-in lanes to pass without skips;
the installed Chromium, pinned adapter environment and cached npm dependencies
must be available. Each run writes new evidence and retains failures.

## Remaining research gates

First, rerun the **new** lifecycle and syntax/dataflow construction corrections
through an actual modest-model TUI when the same free provider becomes available.
Keep equal executor/tool/call budgets and preserve the original failed receipts.
Then evaluate untouched task families against the original accessible harnesses;
predeclare margins and count all unavailable/cancelled/invalid outcomes correctly.

Broader runtime mappings, real browser/SRE tools, production services, physical
laboratories, robotics and clinical operation need their own qualified adapters,
external safety controls and outcome oracles. Source-derived domain skills alone
do not establish deployment readiness. A model can preserve the wording of a goal
while implementing it incorrectly; independent task evaluation remains essential.

The system is a runnable, inspectable research implementation with a substantial
adversarial regression suite. The larger claim—reliably generating very difficult
domain harnesses near specialist-product performance without routine human
repair—remains an empirical research target rather than a completed result.
